## 一、快速开始：如何使用与验收

### 1.1 三种对象的核心问题

系统针对三种分析对象，分别回答对应的核心问题。用户只需输入一个标的代码和一个日期，就能得到三个明确答案：

| 对象 | 核心问题 | 输入示例 |
|:---|:---|:---|
| **个股** | 这只股票当前被什么资金主导？正反馈还是负反馈？持续性如何？ | `--level stock --code 688256` |
| **板块/ETF** | 这个板块/ETF当前被什么资金主导？正反馈还是负反馈？持续性如何？ | `--level sector_etf --code 512760` |
| **大类** | 这个大类当前资金在往哪边倾斜？正反馈还是负反馈？持续性如何？ | `--level sector_macro --code tech` |

三种对象的输出结构一致（`dominant_capital` / `feedback` / `persistence`），但**主导资金的判定逻辑、可用资金类别、评分权重完全不同**（详见第六、八、十章）。

**重要原则**：如果数据确实不足以支撑判断，系统**如实返回“无法判断”**，并给出具体原因与后续优化建议，而不是强行给出一个不可靠的结论。

### 1.2 CLI 使用方式

```bash
# 个股画像
capital-profiler profile --level stock --code 688256 --date 2026-09-01

# 板块/ETF画像
capital-profiler profile --level sector_etf --code 512760 --date 2026-09-01

# 大类画像
capital-profiler profile --level sector_macro --code tech --date 2026-09-01

# 批量查询
capital-profiler batch --level stock --codes 688256,600519,300750 --date 2026-09-01

# 输出为JSON文件
capital-profiler profile --level stock --code 688256 --date 2026-09-01 --output result.json

# 输出为人类可读的文本报告
capital-profiler profile --level stock --code 688256 --date 2026-09-01 --format text
```

### 1.3 Python API 使用方式

```python
from capital_profiler import Profiler

p = Profiler(config_path='config/')

# 三种对象统一调用
result = p.profile(level='stock', code='688256', date='2026-09-01')
# result = p.profile(level='sector_etf', code='512760', date='2026-09-01')
# result = p.profile(level='sector_macro', code='tech', date='2026-09-01')

# 先检查是否能得出明确结论
if result.answer.status == 'resolved':
    print(result.answer.dominant_capital)   # "量化席位+陆股通"
    print(result.answer.feedback)           # "正反馈"
    print(result.answer.persistence)        # "弱（预计1-3日）"
else:
    print(result.answer.undetermined_reason)  # "当日龙虎榜无该股数据..."
    print(result.answer.suggestions)          # ["尝试查询最近一次上榜日期..."]
```

### 1.5 验收标准（用户视角）

| 验收条件 | 检验方式 | 合格标准 |
|:---|:---|:---|
| **可回答** | 三种对象的三个问题都有明确答案，**或**明确说明无法判断的原因 | 不得返回空值或默认值；无法判断时必须给出具体原因与建议 |
| **可解释** | 每个结论都有资金明细作为证据 | 结论与明细方向一致 |
| **可回溯** | 给定日期能复现结果 | 同一日期多次调用结果一致 |
| **可评估** | 结论能被历史数据验证 | 评分与未来波动率IC ≥ 0.04 |

## 二、输入输出契约

### 2.1 输入契约

```python
@dataclass
class ProfileRequest:
    level: str              # 'stock' | 'sector_etf' | 'sector_macro'
    code: str               # 标的代码
    date: str               # 分析日期 YYYY-MM-DD
    lookback_days: int = 60 # 回看窗口（默认60个交易日）
    output_format: str = 'json'  # 'json' | 'text'
```

**输入约束**：
- `level='stock'` 时，`code` 为6位股票代码
- `level='sector_etf'` 时，`code` 为6位ETF代码或板块代码
- `level='sector_macro'` 时，`code` 为大类标识（如 `tech`、`consumer`）
- `date` 不能晚于最新交易日

### 2.2 输出契约

```python
@dataclass
class ProfileResult:
    meta: MetaInfo
    answer: Answer                    # 核心结论（含 status）
    structure_score: Optional[float]  # 无法判断时为 None
    structure_grade: Optional[str]    # 无法判断时为 None
    capital_details: Dict[str, CapitalDetail]
    key_signals: List[Signal]
    warnings: List[str]
    data_quality: DataQuality

@dataclass
class Answer:
    status: str                     # 'resolved' | 'undetermined'
    dominant_capital: Optional[str] # status='resolved' 时有效
    feedback: Optional[str]         # status='resolved' 时有效
    persistence: Optional[str]      # status='resolved' 时有效
    undetermined_reason: Optional[str]  # status='undetermined' 时的具体原因
    suggestions: Optional[List[str]]    # status='undetermined' 时的优化建议
    partial_findings: Optional[Dict]    # 即使无法判断，也列出已确认的信息

@dataclass
class CapitalDetail:
    net_buy: Optional[float]
    direction: str          # "buy" | "sell" | "mixed" | "absent" | "stable" | "unknown"
    proxy_metric: str
    confidence: float       # 置信度 0-1
    note: Optional[str]     # 补充说明（如"数据缺失"）
```

### 2.4 持续性判定规则

`persistence` 字段由以下规则生成（仅在 `status='resolved'` 时有效）：

| 对象 | 主导资金 | 反馈性质 | 持续性判定 | 依据 |
|:---|:---|:---|:---|:---|
| 个股 | 游资/打板 | 强正反馈 | 极弱（1日） | 脉冲式，次日大概率反转 |
| 个股 | 量化席位 | 中性 | 弱（1-3日） | 对冲策略，方向性弱 |
| 个股 | 陆股通席位 | 外生 | 中（1-2周） | 事件驱动，取决于外资整体流向 |
| 个股 | 机构专用 | 正反馈 | 中（1-2周） | 排名压力驱动，跟随趋势 |
| 个股 | 产业资本 | 强负反馈 | 强（1月+） | 回购/增持是长线信号 |
| 个股 | 两融 | 条件依赖 | 中（1-2周） | 杠杆资金，趋势跟随 |
| 板块 | ETF申赎 | 中性 | 长（1月+） | 配置盘驱动，稳定性高 |
| 板块 | 板块龙虎榜 | 正反馈 | 短（1-3日） | 事件驱动，持续性弱 |
| 板块 | 北向板块配置 | 外生 | 中~长（2周-1月） | 季度配置变化 |
| 大类 | 大类ETF申赎 | 中性 | 长（1月+） | 大类配置，稳定性最高 |

## 三、无法判断的处理规范

### 3.1 设计原则

系统**如实返回“无法判断”**，不强行给出不可靠的结论。判断逻辑遵循以下优先级：

1. **优先如实**：数据不足时明确说明，不用默认值填充
2. **保留部分发现**：即使无法判断主导资金，也列出已确认的信息
3. **给出可操作的下一步**：每条“无法判断”都必须附带后续优化建议

### 3.2 无法判断的六种场景

| 场景 | 触发条件 | 返回状态 | 原因说明 | 建议 |
|:---|:---|:---|:---|:---|
| **S1 标的停牌** | 当日无行情数据 | `undetermined` | "当日无交易数据（停牌）" | 查询复牌日期后重试 |
| **S2 数据源缺失** | 关键字段缺失率 > 20% | `undetermined` | "数据源缺失，无法计算" | 检查数据源，或降低回看窗口 |
| **S3 信号全缺席** | 所有资金类别 direction 为 absent/stable | `undetermined` | "所有资金信号均为缺席/稳定" | 扩大回看窗口至20日以上 |
| **S4 信号矛盾** | 正反馈与负反馈资金同时主导，方向相反 | `undetermined` | "正负反馈资金同时活跃，方向矛盾" | 分拆主导资金分别观察 |
| **S5 样本不足** | 回看窗口内有效交易日 < 20日 | `undetermined` | "回看窗口内有效交易日不足" | 扩大回看窗口至60日以上 |
| **S6 历史数据不足** | 分位数计算所需历史 < 60日 | `undetermined` | "历史数据不足，无法计算分位数" | 使用固定阈值替代，或等待数据积累 |

## 七、聚合逻辑与映射规则

### 7.1 个股 → 板块/ETF 聚合

```python
def aggregate_to_sector(stock_metrics, sector_constituents, method='weighted'):
    """
    将个股级指标聚合为板块级
    sector_constituents: {sector_code: {stock_code: weight}}
    """
    sector_results = {}
    for sector_code, constituents in sector_constituents.items():
        stocks = list(constituents.keys())
        weights = np.array(list(constituents.values()))
        
        if method == 'weighted':
            sector_value = (stock_metrics.loc[stocks] * weights).sum()
        elif method == 'equal':
            sector_value = stock_metrics.loc[stocks].mean()
        sector_results[sector_code] = sector_value
    return sector_results
```

**聚合规则明细**：

| 指标类型 | 聚合方法 | 说明 |
|:---|:---|:---|
| 龙虎榜净买入 | 求和 | 板块内所有上榜个股净买入加总 |
| 两融余额 | 求和 | 板块内个股融资余额加总 |
| 两融买入占比 | 加权平均 | 按融资余额加权 |
| 北向季度持股 | 求和 | 板块内个股北向持股加总 |
| 回购/增持金额 | 求和 | 板块内公告金额加总 |
| 股东户数变化 | 加权平均 | 按市值加权 |
| 机构席位净买卖 | 求和 | 板块内机构专用席位净买卖加总 |

### 7.2 板块 → 大类 聚合

```python
def aggregate_to_macro(sector_metrics, macro_mapping, method='etf_scale'):
    """
    将板块级指标聚合为大类级
    macro_mapping: {macro_code: [sector_codes]}
    """
    macro_results = {}
    for macro_code, sectors in macro_mapping.items():
        if method == 'etf_scale':
            scales = np.array([get_etf_scale(s) for s in sectors])
            w = scales / scales.sum()
            macro_value = (sector_metrics.loc[sectors] * w).sum()
        else:
            macro_value = sector_metrics.loc[sectors].mean()
        macro_results[macro_code] = macro_value
    return macro_results
```

## 九、反馈性质判定引擎

| 对象 | 价格序列 | 资金流序列 |
|:---|:---|:---|
| 个股 | 个股日收益率 | 个股资金净流入（龙虎榜+两融+大宗） |
| 板块/ETF | 板块指数/ETF收益率 | 板块聚合资金净流入 |
| 大类 | 大类指数收益率 | 大类聚合资金净流入 |

```python
def detect_feedback(price_returns, capital_flows, window=5):
    """
    反馈性质判定（三种对象通用）
    """
    correlation = rolling_corr(price_returns, capital_flows, window)
    
    if correlation > 0.6:
        return 'strong_positive'
    elif correlation < -0.4:
        return 'strong_negative'
    elif -0.4 <= correlation <= 0.2:
        return 'neutral'
    else:
        return 'conditional'
```

**综合判定矩阵**：

| 价格变动 | 资金流入 | 资金流出 | 判定 |
|:---|:---|:---|:---|
| 上涨 | 加速流入 | — | 强正反馈 |
| 上涨 | — | 加速流出 | 负反馈（压顶） |
| 下跌 | 加速流入 | — | 强负反馈（托底） |
| 下跌 | — | 加速流出 | 正反馈（踩踏） |
| 横盘 | 温和流入 | 温和流出 | 中性 |


## 十、评分体系（三套权重）

### 10.1 个股级评分权重

```python
def calculate_stock_score(stock_metrics):
    """
    个股级结构健康度评分
    核心逻辑：筹码越集中、长线资金越多、正反馈越少，评分越高
    """
    speculative_ratio = (stock_metrics['hot_money_net'] + 
                         stock_metrics['quant_net']) / total_flow
    institutional_ratio = (stock_metrics['institutional_net'] + 
                           stock_metrics['industrial_capital']) / total_flow
    margin_ratio = stock_metrics['margin_buy_ratio']
    shareholder_change = stock_metrics['shareholder_change']
    
    score = (
        0.30 * (1 - speculative_ratio) * 100 +
        0.35 * institutional_ratio * 100 +
        0.20 * (1 - margin_ratio / 0.15) * 100 +
        0.15 * (1 - shareholder_change / 0.2) * 100
    )
    return max(0, min(100, score))
```

```python
def calculate_sector_score(sector_metrics):
    etf_flow_score = normalize(sector_metrics['etf_consecutive_inflow'])
    institutional_score = normalize(sector_metrics['institutional_net_buy'])

        0.30 * institutional_score +
        0.25 * industrial_score +

```

```python
def calculate_macro_score(macro_metrics):

    industrial_score = normalize(macro_metrics['buyback_amount'])
```
