## 一、最重要的定位决策：多周期配置 + 择时

> **系统不是"纯短线择时"，而是"多周期配置 + 择时"。**

原始需求（myor.tmp）的内在矛盾被识别并解决：
- L2 要判断"长(1年+)/中(半年+)/短期"投资价值
- 但第 5 条说微观分析"只用做短期投资策略"
- **矛盾**：L2 判断的长期价值，若 L3 只做短线，则无处落地

**决策**：系统支持多周期。L2 的中长期判断**真的去配置中长期持仓**，不只是背景参考。

### 由此锁定的连锁结论

1. **time_horizon 从"占位"升级为"核心维度"**——它是仓位的根本属性，决定退出逻辑：
   - 长期配置仓：L2 判断行业趋势反转才退出
   - 短期交易仓：L3 技术信号触发就退出
2. **需要"仓位分层管理"**（全新模块，当前缺失）：
   ```
   总仓位（L1 管总上限）
   ├── 中长期配置仓（L2 驱动，按行业价值配置，慢调）
   └── 短期交易仓（L3 驱动，择时波段，快调）
   ```
3. **配置仓/交易仓的资金分配由 L1 决定**（L1 管总风险基调，自然决定"防御时多配置少交易"）
4. **各层时间尺度不同**（问题 A 被锁定）：L1 慢变（周/事件级）、L2 中变（月/季级）、L3 快变（日级）

## 二、三层重定位（基于多周期配置）

```
┌────────────────────────────────────────────────────────┐
│ L1 宏观（慢变，周/事件级）                                                │
│  职责：设定市场模式基调 + 总仓位风险约束 + 配置/交易仓资金分配            │
│  输入：宏观指标 + 重大事件（阶段六）+ 经济周期信号                        │
│  输出：regime/risk_mode + max_position + 配置仓:交易仓 资金比例           │
│        + 对下层的模式约束（允许的风险档位/策略风格大类）                  │
└────────────────────────┬───────────────────────────────┘
                         │ L1→L2 约束
┌────────────────────────▼───────────────────────────────┐
│ L2 行业（中变，月/季级）                                                  │
│  职责：判断行业长/中/短期价值 → 驱动【中长期配置仓】                      │
│        同时向 L3 传递行业池 + 收窄后的策略风格约束                        │
│  输入：L1 模式约束 + 资金流 + 行业基本面 + 产业/科技趋势                  │
│  输出：行业配置方案（含 time_horizon）+ L3 的行业池/风格约束              │
└────────────────────────┬───────────────────────────────┘
                         │ L2→L3 约束
┌────────────────────────▼───────────────────────────────┐
│ L3 个股（快变，日级）                                                     │
│  职责：在 L1+L2 约束内，做【短期交易仓】的择时择股                        │
│  输入：行业池 + 收窄后的风格空间 + 风险档位                               │
│  输出：短期买卖信号                                                       │
│  注：原始需求 L3 是"双子层"（基本面选股 + 技术择时），当前只有技术择时    │
└──────────────────────────────────────────────────────────┘
```

**关键变化**：L2 不再只是"给 L3 收窄范围的中间人"，**它自己就是一类仓位（配置仓）的决策者**。
- L2 的能力 = 中长期行业配置
- L3 的能力 = 短期择时
- 这呼应"每层提供能力"的约束-能力模型

## 三、原始需求中识别出的模糊/不合理点（及处理）

讨论中逐层审视原始需求，识别出的问题与处理方式：

| 编号 | 问题 | 处理 |
|---|---|---|
| **P-1** | L1「感知」与「预测」混为一谈（难度天差地别） | 明确 L1 当前只做"感知/捕获当前状态"，"预测未来场景"作为远期目标 |
| **P-2** | regime 偏「风险情绪」（VIX/PMI），但原文要的是「结构性场景」（地缘/政策/周期） | 承认当前 L1 缺"场景"维度只有"情绪"维度；阶段六补事件感知时升级 |
| **P-3** | L2 信息密度极高（资金流+基本面+趋势+科技），当前只做资金流（最浅一维） | L2 是与原始需求差距最大的层；能力逐步填充（台阶二） |
| **P-4** | L2「长中短期价值」vs L3「只做短期」矛盾 | **已解决**：定位多周期配置，L2 长期判断驱动配置仓 |
| **P-5** | L3 原文含「基本面分析+技术分析」双子层，实现只做了技术 | L3 是"双子层"，当前只实现技术择时，基本面选股待补 |
| **P-6** | 「只做短期」是约束还是现状 | 确认是**现状非约束**（否则 L2 长期判断无意义） |

## 四、实现节奏：两台阶

> **两台阶节奏已确认**：先架构对齐（不返工），能力逐步填充。

### 台阶一（架构对齐，先建骨架）— 本轮~阶段四
- 三层定位、time_horizon 激活、配置仓/交易仓概念**写进文档和 schema**
- decision_context 扩展支持"配置仓约束"和"交易仓约束"两条线
- 仓位分层管理先做**最小版**（能记录一笔仓位是配置仓还是交易仓即可）
- **多频率调度先不做**（仍日频跑，逻辑上区分两类仓位）

### 台阶二（能力填充，后续逐步）
- L2 真正的中长期价值判断（基本面 + 趋势 + LLM）
- 多频率调度（L1 周 / L2 月 / L3 日）
- 配置仓完整的持有/退出生命周期管理
- L3 基本面选股子层

## 五、策略能力画像 schema（已确认设计）

> 这是 L3 层策略的"自我描述"。L1→L2→L3 约束流据此做匹配筛选。

### 6 维 schema（激活 4 + 占位 2）

```python
class BaseStrategy(ABC):
    # ── 现有保留 ──
    name: str = "未命名策略"
    description: str = ""              # 自然语言简述
    version: str = "1.0.0"

    # ══════ 激活维度（4个，有消费逻辑）══════
    applicable_regimes: list[str] = ["balanced"]   # ① 适用 regime（多值，主筛依据）
    #   取值：crisis / risk_off / balanced / risk_on / volatile（对齐 L1 regime）
    style: str = ""                                 # ② 策略风格（LLM 匹配 + 人看）
    #   取值：momentum / value / quality / reversal / moneyflow / breakout
    applicable_scenario: str = ""                   # ③ 适用场景（自然语言，供 LLM 语境推理）
    risk_profile: str = "balanced"                  # ④ 风险风格（声明 + 校验，不独立筛选）
    #   取值：defensive / balanced / aggressive

    # ══════ 占位维度（2个，仅留位，本期不造消费逻辑）══════
    time_horizon: str = "short"                     # ⑤ 时间周期（为中长期策略留位）
    #   取值：short(日内~周) / medium(半年+) / long(1年+)
    data_dependency: list[str] = ["technical"]      # ⑥ 数据依赖（为未来鲁棒性留位）
    #   取值：technical / fundamental / moneyflow / macro

    # ── 旧字段：保留向后兼容，标注 deprecated ──
    market_condition: str = "range"   # @deprecated 用 applicable_regimes 替代

    def profile(self) -> dict:
        """返回策略结构化画像，供 select_strategies / LLM / list_strategies 消费"""
        ...
```

### 核心设计决策

1. **applicable_regimes（多值）是筛选"事实来源"**——替代旧的单值 market_condition（表达力不足）
2. **risk_profile 不独立筛选，是"声明 + 一致性校验"**：
   - 解决 regime（5种）与 risk_mode（3种）双路径冲突的语义重叠问题
   - 校验规则：策略的 risk_profile 应与 applicable_regimes 自洽（如 aggressive 不应适用 crisis），防填错
3. **机器标签 + 自然语言双轨**：标签供规则做确定性掩码（便宜可回测），自然语言供 LLM 做语境推理
4. **time_horizon/data_dependency 占位**：只定义 + 填默认 + 标注预留，**本期不造消费逻辑**（避免无数据可验证的假逻辑）

### time_horizon 的特殊性（多周期配置下）
虽列为"占位"，但因系统定位多周期配置，它实际是**仓位的根本属性**。台阶一先在 schema 留位（策略可标 short/medium/long），台阶二随中长期策略和仓位分层管理真正激活其消费逻辑。

### 业界参考来源
- **Barra 风险模型**：用正交风格因子描述资产/策略 → 多维正交标签
- **RL action masking**：上层状态生成掩码屏蔽不适用动作 → applicable_regimes 作为前置条件
- **Capability Descriptor / Service Manifest**：插件自描述能力 → profile() 方法
- **LLM Tool/Function Schema**：机器可读 + 自然语言描述 → 双轨设计

## 六、下一步：L1→L2→L3 约束 schema 设计（甲方案）

> 待讨论：这是"层间约束传递"的设计，区别于上面的"策略能力画像"。

识别出当前实现的**层次错位**：
- 策略选择当前发生在 **L1**（macro_regime_node 直接调 select_strategies 选好 strategy_keys）
- L2 只筛行业池，**不参与策略空间约束**
- 即"L1 跳过 L2 直连 L3"，**L2→L3 的策略约束缺失**

需设计两套 schema（区分清楚）：
| Schema 类型 | 是什么 | 状态 |
|---|---|---|
| 策略能力画像 | L3 每个策略的自我描述 | ✅ 已设计（本文档 §五） |
| 层间约束 schema | L1→L2、L2→L3 各传什么约束 | ⏳ 待设计 |

**已确认采用甲方案**（先建通道）：
- decision_context 扩展逐层收窄字段（allowed_styles / allowed_risk_profiles / time_horizon_preference / 配置仓约束 / 交易仓约束）
- L1 填、L2 可收窄、L3 消费的**通道先建对**
- L2 的"行业→策略风格"具体映射逻辑**先简单或直通**（先接管道，再灌智能）

> 待下一轮讨论确定：decision_context 完整字段定义、各层填充/收窄/消费的职责划分、配置仓与交易仓两条约束线如何并存。
