## 三、设计/编码阻塞项（必须补全才能动手）

### 3.1 Web 看板完全无规格（F6）——影响 3 个 P0

**问题**：F6.1 信号页、F6.2 指令单页、F6.3 数据状态页，全部只有一句话描述。

**缺失内容**：

- [ ] 页面布局（列表页 + 详情展开？单页？多 tab？）
- [ ] API 端点列表和请求/响应格式
- [ ] 前端技术栈（目前 web/ 目录下 static/ 和 templates/ 均为空目录）
- [ ] "展开辅助分析面板"的具体 UI 结构（字段列表、排序、分组？）
- [ ] 指令单页的确认/取消交互流程（弹窗确认？直接按钮？）

**后果**：后端生成信号后，前端开发没有规格可参考；自动化测试（Selenium/Playwright）无法写入。

### 3.2 推送消息无模板和长度约束（F5.1）——影响 1 个 P0

**问题**：只说"包含基本面摘要和资金流关键指标（精简版）"，未定义：

- [ ] 精简版包含几个字段
- [ ] 消息总长度上限（企业微信 Markdown 2048 字节，20 条信号 push 必然超限）
- [ ] 超长时的处理策略（分多条？只推 Top N？截断？）
- [ ] 消息模板示例（Markdown 格式）

**后果**：开发推送模块时无法确定每条消息塞多少信息，实现后必然返工。

### 3.3 数据缺失/异常行为未定义——影响 ~5 个 P0

| 场景 | 影响的需求 | 需要决策 |
|---|---|---|
| 某股票没有 moneyflow 数据 | F3.2 | 跳过该字段？标 N/A？该信号不推送？ |
| fundamental 数据落后一期 | F3.1 | 用上期数据还是留空？标注"数据滞后"？ |
| 行业分类缺失（退市/新上市） | F3.3 | 标"未知"还是隐藏行业区块？ |
| 扫描中单只股票报错 | F2.1 | 跳过继续？整个批次失败？记录日志继续？ |
| 数据更新中途崩溃 | F1.1 | 重启后从断点续传还是从头来？已更新的域是否标记 dirty？ |

**后果**：开发时只能靠猜测，必然出现三种情况——边界 case 崩溃、信息展示不一致、异常处理缺失。

### 3.4 准确性验收标准无法落地（F3 + F4.1）

验收标准第 2 条："信息完整且准确"。怎么验证？

- [ ] 辅助分析字段是直接复制源数据还是经过计算？如果是计算，公式是什么？
- [ ] 同一只股票 AKShare 和 Tushare 给出的 PE/PB 不一致时以谁为准？
- [ ] "准确"的验证方法：人工抽样？自动化对比？对比哪个参考数据？

**后果**：测试人员无法写出有意义的 assert，只能写"字段非空"，达不到验收标准。

## 八、结论

**当前需求文档不能直接支撑 Phase 1 全部功能的设计和编码。**

- **可以直接上手的**：F1 数据更新、F2 扫描、F4.2~F4.4 指令单管理、F5.2 推送渠道、F7 可观测性
- **补完规格后可上手的**：F3.1~F3.5 辅助分析字段聚合（数据缺失处理规则补完后）
- **完全无法上手的**：F6 全部（Web 看板零规格）、F5.1 推送内容（无模板）

测试覆盖率方面，24 个功能点中仅 9 个可写出有效测试用例，10 个因规格缺失而阻塞——**可测试率仅 37.5%**。
