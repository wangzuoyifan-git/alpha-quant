## 〇、本文档要回答的根本问题

在写任何 LLM 代码之前，必须先回答四个会决定整个系统形态的问题：

1. **LLM 在系统里是什么角色？** —— 边角料，还是认知大脑？
2. **LLM 与规则如何分工？** —— 各管一摊，还是融合裁决？
3. **LLM 的判断有多大权力？** —— 谁来踩刹车，怎么逐步放开？
4. **这个分工是固定的吗？** —— 还是能随绩效反馈持续进化？

本文档的结论（详见后文）：

> **LLM 是分层的"认知融合者"，把规则产出的结构化证据 + 非结构化信息综合成方案；
> 其方案能否驱动执行，由"自主度分级（autonomy_level）"这个总闸门控制；
> 规则与 LLM 的分工边界，随绩效反馈通过"进化飞轮"持续演进，但守住人工守门红线。**

## 一、设计溯源：回到原始需求

原始需求（`docs/archive/myor.tmp`）描述的是一套**分层、信息密集、需要认知推理**的策略：

| 层 | 原始需求 | 需要的能力 |
|---|---|---|
| L1 宏观 | 地缘政治、美联储/各国货币与产业政策、经济周期信号（金融/流动性危机） | **非结构化文本理解 + 事件预测** |
| L2 行业 | 资金流判断估值 + 行业基本面趋势 + 经济规律/科技趋势预测 + 长中短期价值 | **量化数据 + 跨领域定性推理** |
| L3 个股 | 企业基本面分析 + 技术分析/因子挖掘 | **财报语义理解 + 技术因子** |
| 切换 | 上层信号变化 → 切换下层策略模式（风险/稳健、行业/标的切换） | **跨层联动决策** |

**关键洞察**：原始需求的每一层都需要"规则做不到的认知"。当前实现（阶段一~三）把这些降维成了规则阈值（L1=几个宏观数字、L2=资金流排名、L3=技术规则），**这是为了先搭骨架的合理简化，但不能是终点**。

**LLM 的使命**：补上每一层被规则降维掉的"认知维度"，让系统回归原始需求的深度。

## 二、核心模式：融合，而非分工

### 2.1 两种模式对比

**分工模式（已否决）**：
```
规则 → 自成闭环产出 regime/信号
LLM  → 旁路解读新闻，结果与规则并列，无人汇总
```
缺陷：规则结论与 LLM 认知割裂，没有任何环节把"VIX=35（规则判 risk_off）"与"美联储转鸽（LLM 判利好）"放在一起权衡。LLM 被边缘化。

**融合模式（采纳）**：
```
规则层 → 产出结构化"证据"（确定、可复现、可回测）
            +
非结构化信息（政策文本/新闻/研报）
            ↓
LLM 作为"综合分析师" → 综合研判 + 方案建议 + 结构化推理链
```

### 2.2 关键视角转变：规则从"决策者"降为"证据提供者"

- 分工模式：规则是**独立决策者**（自己出 regime/信号），LLM 是旁观者
- 融合模式：规则是**证据/特征提取器**（把市场状态结构化成"事实"），LLM 是**综合决策者**

各司其职：
- **规则擅长**：快速、确定、可复现地把原始数据加工成结构化结论
- **LLM 擅长**：把多源结构化结论 + 非结构化信息做加权推理，输出带理由的方案

这正是真实基金经理的工作方式——"技术面显示该减仓，**但**结合美联储鸽派信号和资金流仍流入，我判断是短期恐慌而非趋势反转，**所以**维持仓位但收紧止损"。这句话融合了规则结论 + 文本认知 + 量化数据 → 综合方案。

### 2.3 融合模式的三个风险与应对（必须正视）

| 风险 | 说明 | 应对 |
|---|---|---|
| **污染确定性** | 规则可复现，LLM 不确定；最终由 LLM 综合则决策继承不确定性 | 规则结论**完整保留、独立可追溯**；LLM 综合是"附加层"，受 autonomy_level 控制是否驱动决策 |
| **grounding 更难** | LLM 引用规则数字推理，可能曲解/编造 | 规则结论以**结构化、带标签**注入（"以下是系统事实，禁止修改，只能基于它们推理"）；输出要求**回引**用了哪些证据 |
| **可解释性** | "维持仓位但收紧止损"——为什么？推理链不清则难复盘 | 强制 LLM 输出**结构化推理**（用了哪些证据/各自权重/结论），而非自由文本 |

## 三、架构形态：双向"约束-能力"分层协商（非加权）

> **重要修正（2026-06-12）**：早期草案曾设计"分层加权"（每层 LLM 结论带权重 w1/w2/w3，顶层加权汇总成单一选择）。
> **该方案已否决**。它把多层判断压成数字再综合，丢失了层次语义和可解释性。
> 采纳的是**约束流 + 能力画像**模型：上层收窄下层动作空间，下层声明能力画像，
> 最终选择是"约束与能力在每层的交汇筛选"，而非加权平均。

### 3.1 核心模型：约束向下、能力向上

```
┌──────────────────────────────────────────────────────────┐
│ L1 宏观                                                                   │
│  自上而下：基于宏观判断，设定"什么模式/风格被允许"的约束（不直接选策略）  │
└────────────────────────┬─────────────────────────────────┘
              约束↓（收窄空间）        ↑能力画像（可选能力 + 特性 + 适用场景）
┌────────────────────────▼─────────────────────────────────┐
│ L2 行业                                                                   │
│  在 L1 约束内，进一步收窄对 L3 的约束；自身决策中长期配置                  │
└────────────────────────┬─────────────────────────────────┘
              约束↓                    ↑能力画像
┌────────────────────────▼─────────────────────────────────┐
│ L3 个股/策略                                                              │
│  在 L1+L2 约束内，用策略能力画像匹配，执行短期择时                        │
└──────────────────────────────────────────────────────────┘
```

**两条信息流**：
- **向下：约束流**——上层不直接替下层选择，而是**收窄下层的动作空间**（"只允许防御型策略""只看这些行业"）
- **向上：能力画像**——下层声明"我能提供什么能力 + 各自特性 + 适用场景"

**与加权模型的本质区别**：加权把多层判断压成数字再综合（丢失语义）；约束-能力模型保持每层语义完整，通过"约束传递 + 能力筛选"做空间收窄，保留"为什么选这个"的可解释性，且层间解耦。

### 3.2 重要决策：运行时只做单向约束流

> 讨论结论（2026-06-12）：**运行时的"向上能力声明流"暂不做（YAGNI）**。

- **向下约束流**：价值明确（阶段二 `allowed_industries` 已验证），**现在就做**
- **向上能力声明流（运行时）**：
  - 曾考虑用于"降低 L1 成本"，但分析表明收益极小（L1 成本主要在输入处理，非输出精度），且有更直接手段（缓存/OFF/按需触发）
  - 唯一站得住的用途是"动态能力失效需上层感知"的**鲁棒性**场景，但当前未出现 → **暂缓**
- **下层静态能力元数据**（策略画像 schema）：**必须做**，它在设计/配置时就被上层约束流消费，**不需要运行时声明流**

### 3.3 LLM 在约束-能力模型中的位置

LLM 不是"输出加权数字"，而是做两件规则做不到的事：
1. **约束的语义解读**：把 L1 的复杂场景（"鸽派防御市但科技资金流入"）解读成对下层的细腻约束
2. **能力-约束的语境化匹配**：当简单标签匹配（regime↔策略标签）不足以应对复杂语境时，LLM 介入做更细的筛选

简单匹配（标签对标签）由规则做（确定可复现）；复杂语境匹配由 LLM 做（受 autonomy_level 约束）。

### 3.4 LLM 综合层形态：分层（每层一个脑），非集中

| | 集中式（否决） | 分层式（采纳） |
|---|---|---|
| 形态 | 一个 LLM 吃 L1+L2+L3 全部证据 | 每层一个 LLM 脑综合本层证据与信息 |
| 优点 | 简单 | 责任清晰、贴合分层精神、各层可独立配置 autonomy_level |
| 缺点 | prompt 巨大、责任不清、难调试 | 调用多、链路长 |

每层 LLM 综合**本层**的规则证据 + 非结构化信息，产出本层研判与约束，向下传递。**不做"顶层加权汇总"**——下层接收的是上层的约束（收窄），不是上层的加权分数。

## 四、自主度分级（autonomy_level）：LLM 方案的执行权总闸门

### 4.1 定位修正（重要）

> **旧定位（已废弃）**：autonomy_level 控制"LLM 能否微调 confidence（±0.2）"——这是把 LLM 当橡皮图章的过度保守设计。
>
> **新定位（采纳）**：autonomy_level 是**"LLM 综合方案能否穿透到执行层"的总闸门**。它控制的不是"LLM 输入什么"，而是"LLM 的产出有多大权力"。安全性由"闸门"保障，而非由"阉割 LLM 输入"保障。

### 4.2 五级定义（修正后）

| 级别 | 名称 | LLM 方案的权力 | 规则的角色 | 闸门状态 |
|---|---|---|---|---|
| **L0** | OFF | LLM 完全不参与 | 规则独立决策（= 阶段三现状） | 关闭，永久可回退的安全基线 |
| **L1** | ADVISORY | LLM 综合方案**只进日志/推送给人看**，不碰决策 | 规则证据照常驱动执行 | 关闭，LLM 旁路记录 |
| **L2** | ASSIST | LLM 可在**限定范围内微调**规则结果（如候选排序、confidence、参数建议） | 规则主导，LLM 修饰 | 半开（受限） |
| **L3** | COPILOT | LLM 可提出**与规则不同**的方案，但需**规则校验/人工确认**才生效 | 规则校验 + 人工守门 | 半开（需确认） |
| **L4** | AUTO | LLM 综合方案**直接驱动决策** | 规则退为**风控兜底** | 全开（你要的闭环） |

### 4.3 关键特性

1. **全局可配置 + 可分层配置**：`config.settings.LLM["autonomy_level"]` 全局默认，且支持每层独立覆盖（如 L1 宏观=ASSIST，L3 个股=ADVISORY）
2. **永远可一键回退 OFF**：不管 LLM 多智能，必须能瞬间关掉回到纯规则。这是量化系统的安全底线。
3. **平滑演进**：随你对 LLM 的信任增长，逐级调高，**无需改架构、改代码**
4. **红线参数化**：所有"红线"（如 confidence ±0.2 限幅）变成"某个级别下的可配参数"，而非硬编码天花板

### 4.4 演进路径

```
阶段四起步：全局 OFF/ADVISORY（搭框架、验证链路、积累决策日志）
   ↓ 随绩效验证与信任增长
逐层、逐步：ASSIST → COPILOT
   ↓ 长期，且需可靠性工程充分验证
个别成熟层：AUTO（打通闭环）
```

## 五、规则-LLM 进化飞轮：动态可进化的分工

### 5.1 设想来源

用户设想：**让每层 LLM 与规则的分工动态可进化——通过绩效反馈持续学习，把 LLM 总结的有价值策略沉淀为规则，从而持续降低各层 LLM 的成本和不确定性。**

本质是 **"探索→固化→再探索"飞轮**：LLM 在规则的边界外探索，验证有效的固化为规则，规则扩大后 LLM 成本下降、专注更前沿的不确定边界。

### 5.2 必须戳破的幻觉：金融不是围棋

AlphaZero 能自进化，靠三个**金融市场根本不具备**的条件：

| AlphaZero 条件 | 金融现实 | 后果 |
|---|---|---|
| 奖励信号完美且即时 | 奖励是噪声海洋，alpha/beta 归因极难 | 可能把"运气"固化成"规则" |
| 环境平稳（规则不变） | 市场非平稳，策略会突然失效 | "学到昨天的真理，死在明天" |
| 样本无限（自我对弈千万局） | A股周期样本极稀少（一生 5-6 次牛熊） | 统计上不足以"学会"宏观判断 |

**结论**：飞轮可以转，但**转速必须慢、必须有人盯着、绩效归因必须极度保守**。任何"系统自动越学越聪明、自动上线新策略"的浪漫想象，在金融里就是**自动化地把过拟合和噪声固化成代码**。

### 5.3 四级自进化（按风险分级）

| 层次 | 自进化对象 | 风险 | 策略 |
|---|---|---|---|
| **L-A 参数自优化** | 阈值/权重（VIX 阈值、行业池 Top N、各层 LLM 权重） | 低 | ✅ **自动化**（改数值，错了易回退） |
| **L-B 经验记忆库** | LLM 反思沉淀为结构化经验，反哺未来 LLM 的 prompt | 低-中 | ✅ **半自动**（改提示，不改逻辑） |
| **L-C 规则候选 + 人工审核** | LLM 提议新规则逻辑，人审核后固化为代码 | 中 | ✅ **LLM 提议 + 人工守门** |
| **L-D 自动写可执行代码** | LLM 自动生成规则代码并直接部署上线 | **极高** | ⚠️ **架构预留可行性，当前不实现**（见 5.5） |

### 5.4 进化飞轮架构

```
┌──────── LLM 探索层（高自主、高成本、高不确定）────────┐
│  对规则覆盖不了的新情况做判断，记录"判断 + 理由 + 证据引用"  │
└────────────────────┬─────────────────────────────┘
                     │ 决策日志（阶段三 node_audit 已奠基）
┌────────────────────▼─────────────────────────────┐
│  绩效归因层（关键守门：保守、统计显著性、区分 alpha/beta）    │
│  阶段五"收益回填"是这一层的起点                              │
└────────────────────┬─────────────────────────────┘
                     │ 沉淀候选
   ┌─────────────┼──────────────────┐
   ▼ L-A 自动     ▼ L-B 半自动        ▼ L-C 人工守门
 参数优化       经验记忆库          规则候选
（阈值/权重     （结构化反思         （LLM 提议 → 人审核 →
  自动微调）      注入 prompt）        才固化为代码）
   └─────────────┴──────────────────┘
                     │ 固化后
┌────────────────────▼─────────────────────────────┐
│  规则层扩大（确定、便宜、可回测）→ LLM 不必再算这部分        │
│  → LLM 成本↓、不确定性↓、专注更前沿边界 ← 飞轮闭合          │
└──────────────────────────────────────────────────┘
```

**精髓**：
- 自动化的只有 **L-A（参数）+ L-B（经验记忆）**——改数值和提示，不改可执行逻辑，错了易回退
- **L-C（新规则逻辑）永远人工守门**——LLM 只能"提议"，人"审批"，通过才进代码。保留进化能力，守住不可控风险

### 5.5 关于 L-D（自动写代码）：架构预留，当前不实现

用户要求：**L-D 在架构上尽量考虑可行性（具体实现看后续技术发展）。**

**当前不实现的理由**（三个杀手）：
1. **绩效归因不可靠 → 固化的是噪声**：把幸存者偏差写进系统 DNA
2. **正反馈失控**：LLM 生成规则→影响交易→绩效反馈 LLM→自我强化，无人在回路则错误滚雪球
3. **不可解释的技术债**：半年后 200 条互相耦合的自动规则，无法复盘/关停单条 → 对管真金白银的系统是灾难

**但架构上预留可行性**，使未来技术成熟时能平滑接入，需在设计时满足：
1. **规则可插拔**：规则以统一接口注册（如策略注册表模式），新规则（无论人写还是 LLM 写）走同一注册/加载机制
2. **规则带元数据**：每条规则标注来源（human / llm_proposed / llm_auto）、生成时间、绩效依据、可独立启停
3. **生成-验证-上线分离**：即使未来 L-D 自动生成，也必须经过"沙盒回测 → 样本外验证 → 灰度"的管道，而非直接上线
4. **决策日志足够细**：LLM 的每次判断带"证据引用 + 结构化推理"（阶段四就要做），为未来自动归因留数据
5. **autonomy_level 与进化解耦**：L-D 生成的规则，其执行权仍受 autonomy_level 闸门约束

> **设计原则**：L-D 的"门"在架构上留着（接口、数据流、元数据都支持），但"门后的自动生成引擎"当前不建。未来技术（LLM 可靠性、归因方法）成熟时，补上引擎即可，无需重构。

## 六、autonomy_level 与进化飞轮的关系（正交）

两个概念控制不同的东西，正交组合构成系统的安全框架：

```
                    进化飞轮（控制"规则与 LLM 的分工边界"）
                    L-A 参数 → L-B 记忆 → L-C 规则 →(L-D 预留)
                         │
autonomy_level           │  随时间，规则边界外扩，LLM 专注前沿
（控制"LLM 方案的        │
  执行权大小"）          │
   OFF                   │
   ADVISORY    ──────────┼──────────  分工边界在移动
   ASSIST                │
   COPILOT               │
   AUTO                  │
```

- **autonomy_level**：纵轴——LLM 当前能做的判断，有多大权力落地执行
- **进化飞轮**：横轴——哪些判断该由 LLM 做、哪些已沉淀为规则

二者独立调节：可以"低自主度 + 快速进化"（LLM 只建议但持续沉淀经验），也可以"高自主度 + 慢进化"（信任 LLM 落地但谨慎固化规则）。

## 七、对阶段四~六规划的影响

基于本纲领，原阶段四~六需重新定位（细化设计待讨论后写入 `docs/agent.md`）：

| 阶段 | 原定位 | 修正后定位 |
|---|---|---|
| **阶段四** | LLM 接入（仅外围，微调 confidence） | **LLM 接入地基 + 自主度框架**：①`llm_clients/` 洋葱架构 ②autonomy_level 全局/分层可配机制（默认 OFF/ADVISORY）③L1 作为**首个融合试点**（规则证据 + 双视角研判 → 结构化推理输出）④**每次 LLM 判断带证据引用+结构化推理落盘**（为飞轮铺数据，接续阶段三 node_audit） |
| **阶段五** | 反思闭环（绩效驱动 select_strategies） | **绩效归因层 + 进化飞轮 L-A/L-B 起步**：收益回填 → 保守归因 → 参数自优化（L-A）+ 经验记忆库（L-B） |
| **阶段六** | 宏观事件感知（补全 L1） | **信息层接入 + L1 认知升级**：结构化事件（FOMC 日历等）+ 非结构化信息（新闻/政策）→ 喂给 L1 脑，让 L1 从"几个数字"升级为真正的"宏观场景感知" |

**关键顺序调整建议**：L1 输入的"信息丰富度"是 LLM 价值的前提。当前 L1 只有几个滞后指标，LLM 价值有限。需考虑把阶段六的**结构化事件部分**适当前置（或与阶段四并行），让 L1 试点有真东西可分析。

> 待讨论确认：阶段顺序是否调整、各层 autonomy_level 初始值、分层加权初始策略。

## 八、设计原则总结（红线）

1. **规则永远完整保留、独立可追溯**——LLM 是附加认知层，不替换规则的确定性根基
2. **OFF 永远可一键回退**——不管 LLM 多智能，必须能瞬间回到纯规则
3. **grounding 强制**——数值来自规则/store，LLM 禁止生成数字，输出须回引证据
4. **结构化推理强制**——LLM 输出推理链（用了哪些证据/如何权衡/结论），非自由文本，保可解释
5. **L-D 不自动上线**——规则逻辑的固化永远经人工守门或"沙盒→样本外→灰度"管道
6. **autonomy_level 是执行权闸门**——安全靠闸门，不靠阉割 LLM 输入
7. **核心信号路径的"规则证据生产"仍可回测**——LLM 综合层之下的规则证据，确定可复现
