## 一、席位字典（游资/量化识别）

### D1. 外部字典 xlsx 的标签口径冲突（游资别名 vs 资金类型）
- 背景：`reference/A股龙虎榜席位资金画像字典.xlsx` 中，43 条有“游资别名（数据侧标签）”，其中 39 条资金类型=游资，另有 4 条（拉萨天团→东方财富拉萨系）资金类型=散户集群，二者语义冲突。
- 备选：
  - A. 资金类型为准，别名仅作 tag
  - B. 有游资别名即算游资
  - C. 冲突项不入库
- **决策：A**（用户确认）。理由：资金类型是行为实测，别名是江湖名号；拉萨系业内更接近散户/量化通道。

### D2. 低频营业部 + 样本不足（1693 行）是否入库
- 备选：A. 不导入，交给软标签聚类；B. 导入为“普通营业部”（低置信）
- **决策：A**（用户确认）。理由：置信度仅 10，作为标签无意义且会污染。

### D3. 席位ID 冲突（23 处同名/跨券商重复）
- 背景：同一席位ID 对应两个不同营业部（含跨券商碰撞，如 03141791 东方证券/东海证券）。
- 备选：A. 以“营业部名称”为键、席位ID 仅存档；B. 暂停核对源
- **决策：A**（用户确认）。理由：名称与本地 `top_inst` 100% 精确匹配，可直接消费；ID 不可靠。

### D4. 软标签聚类命名：无硬标签时“游资/量化”如何命名
- 背景：首版启发式把“高频+买卖同席”的大通道（高盛/瑞银/拉萨/中金）误判为游资。
- 备选：A. 修正评分（高频+同席+分散→量化；快进快出+集中→游资）；B. 名称由硬标签锚定，无硬标签不给游资/量化名
- **决策：A+B 结合**：既修正评分，又加“**硬标签纯度门槛 ≥50%**”——某簇硬标签纯度不足则不给该簇软命名（归“普通营业部”）。

### D5. 硬标签锚定后的簇命名
- **决策**：有硬标签时按“簇内硬标签纯度”锚定 —— 对每个簇计算 `该簇中某类硬标签数 / 该簇硬标签总数`；游资/量化各自取纯度最高且 `>= purity`（**默认 0.6**，2026-09-29 由 0.5 收紧）的簇命名；两者若指向同一簇则归给纯度更高者；其余簇 = 普通营业部。

### D6. 字典键与匹配方式
- **决策**：以营业部全称为键；`_match_hard_label` 用子串匹配（兼容“证券营业部/营业部”写法差异）；同名多行合并（取最高置信、合并 tag）。
- 已知局限：子串匹配可能把“XX分公司”误配到“XX分公司二部”等同名族，风险由名称唯一性（1824 名均唯一）与人工复核控制。

### D7. 置信度口径
- 硬标签：`confidence = xlsx 置信度(0-100)/100`。
- 软标签：`conf = clamp(0.35 + 0.40*sample + 0.25*posterior_margin, 0.30, 0.95)`，其中 `sample = 1 - exp(-freq/min_appearances)`。
- **决策**：保留该公式；软标签置信度上限 0.95（不宣称确定）。

### D8. 衰减与刷新周期
- **决策**：`half_life_days = 90`；每周脚本（`update_weekly.sh`）执行 `seat-dict import`（xlsx 更新时）+ `seat-dict build`（重估）。
- 备选：季度刷新（更省，但对 40 日样本窗口反应慢）→ 未采纳。

### D9. 生成物是否入库
- **决策**：`seat_dictionary.json/csv/report.md`、`seat_labels.json` 均视为生成物 → `.gitignore` 排除；xlsx 源（reference/）入库，可重建。

### D10. 覆盖范围
- 外部字典覆盖 1824/12489 席（约 15%）；未覆盖席位由行为聚类软标签或“普通营业部”承接。
- **决策**：接受；后续可通过扩样本窗口/更多数据源提高覆盖。

## 四、Phase 1（个股级资金画像）实现决策

### D14. 资金类别与阈值
- **决策**：六类 = hot_money/quant/institutional/northbound/margin/industrial_capital。
- 阈值：**业界通用，对齐 `reference/资金画像0.1.md` 11.3 `thresholds.yaml`**：龙虎榜类 `|净额| ≥ 5000万`；陆股通 `≥ 3000万`；两融变动率 `≥ 3%`；产业资本（回购/增持）`≥ 1亿`。低于阈值记 `stable`；窗口内无该信号记 `absent`；无数据记 `absent/unknown`。

### D15. 反馈性质口径
- **背景澄清**：`moneyflow/stock` 按**单笔成交金额档位**（小/中/大/超大单）分类，**不区分席位或资金主体**；席位级方向由 `dominant_capital`（top_inst + 席位字典 + hk_hold + margin + events）负责，二者分工不同。
- **决策**：`feedback = corr(价格日收益, 主力资金净流入)`，主力口径 = `(buy_lg+buy_elg) - (sell_lg+sell_elg)`；缺该组合时回退 `net_mf_amount`。取窗口内日频对齐；`>0.6 强正 / <-0.4 强负 / -0.4~0.2 中性 / 其余 条件依赖`。
- 理由：feedback 只需一条**连续日频**资金净流向序列与价格算相关性；龙虎榜（top_inst）为事件级稀疏，做日频相关性会大量缺日。用主力（大单+超大单）口径比全单 `net_mf_amount` 更贴合“主力 vs 价格共振”。
- 后续可选：融合“席位级事件流”（龙虎榜+两融+大宗）作为合力/分歧子信号。用户确认（2026-09-29）。

### D16. 结构评分权重（无股东户数维度）
- **决策**：**权重对齐业界通用 `reference/资金画像0.1.md` 10.1**：投机 0.30 / 机构 0.35 / 两融 0.20（+ 股东户数 0.15，本项目无该数据），按可用维度重归一。
  `score = w1*(1-spec)*100 + w2*min(inst_ratio,1)*100 + w3*(1-|margin_rate|/0.15)*100`；无任何资金数据则 `None`（无法判断）。

### D17. 主导资金选择
- **决策**：对 direction ∈ {buy,sell} 的类别计算 `strength = |net|/阈值`，取 `strength ≥ 1 且最大` 者；若同时存在超阈买入与超阈卖出类别 → **S4 矛盾**（无法判断）。

### D18. 产业资本口径
- **决策**：用 events E2 的 `increase`（增持）/`reduce`（减持/质押）事件；有增持→买入方向（金额=change_vol×avg_price，缺失时仅方向）；有减持→卖出方向；无→absent。
- 说明：数据源无独立“回购”事件类型，回购暂以增持近似/待补。

### D19. CLI 命名与落位
- **决策**：`main.py capital-profiler profile --level stock --code ... [--date --lookback --format json|text]`；实现于 `agents/capital_profiler.py`（非独立包）。
- 理由：与项目“agents/ + main.py 子命令”惯例一致；`reference/资金画像0.1.md` 保留为参考原件。

### D20. 软标签的显式标注（2026-09-29 用户要求）
- **决策**：CLI 所有“席位身份/标签”列加来源短标记**前缀**：`[硬]`=数据源硬标签、`[软]`=行为聚类软标签、`[规则]`=规则匹配、`[推断]`=别名推断。
- 字典记录与 JSON 输出仍保留完整 `label_basis`；Markdown 报告写全称。
- 实现：`main.py` 的 `_seat_basis_mark()`。

### D21. 中度收紧软标签（2026-09-29 用户同意）
- **决策**：默认参数收紧为 `min_appearances=10`、`purity=0.6`、`soft_min_conf=0.7`；软标签置信度低于 0.7 **不入库**（该席位回落为“普通营业部”）。
- 备选（未采纳）：保持 `purity=0.5` + 输出全部软标签（覆盖更广但噪声多）。
- 效果：量化席位 276 → 176（其中软标签 199 → 99）；软标签最低置信 0.7。

### D22. 软标签不做人工复核（2026-09-29 用户决定）
- **决策**：不人工复核 top 软标签；软标签统一带 `[软]` 前缀 + 置信度，由使用者酌情处理。
- 理由：用户明确表示自行判断。至此“软标签污染”相关事项闭环。

### D23. 席位字典“生效时间分段”：先快照、后完整分段（2026-09-29 用户同意）
- 背景：席位会随时间变化（更名/迁址/游资换席/ID 碰撞），单标签会失真；但外部 xlsx 仅 40 日窗口，暂无可分段历史。
- 备选：
  - A 维持现状（单标签 + 定期覆盖）
  - B 轻量快照归档（每次 build 存带日期快照，历史查询取“截至该日最近一次”）
  - C 完整分段（记录带 `[effective_from, effective_to]`，查询按日期取段）
- **决策：先做 B，C 待历史足够（≥1 年）再做。**
- 实现：`build_seat_dictionary` 每次落地 `data/smart_money/snapshots/seat_dictionary_YYYYMMDD.json`（同日覆盖幂等，保留最近 60 份）；新增 `list_snapshots()` / `load_snapshot_asof(date)` 供回看。
- 后果：当前 `classify_seat` 仍用最新字典（未按日期），历史回看的“分段应用”待 C。

### D24. 席位视图 × 主力视图一致性（Phase 1 增强，2026-09-29）
- 背景：席位视图（`top_inst`+字典）事件级/稀疏、能识别主体；主力视图（`moneyflow/stock`）日频/连续、不区分主体。二者正交互补。
- **决策**：以“上榜事件”为锚点做交叉，输出：
  - `main_flow_daily`：窗口主力净流入合计 + 连续同向天数（背景）
  - `seat_vs_main`：窗口聚合的席位方向 × 主力方向四象限（合力向上/合力向下/对倒诱多/隐性吸筹）
  - `seat_main_signals`：上榜前 5 日（提前吸筹）/ 上榜后 5 日（拉高出货风险）
  - dominant 校准：一致性只做 key_signals/warnings 补充，不直接改选主体（避免过度干预）
- **未上榜股票**：默认仍 S3；新增 `--hidden-main` 开关，开启且主力连续同向（≥3 日）时给“隐性主力（日频，弱推断）”弱结论（`answer.weak=true`）。**默认关闭**（保持“数据不足如实说”原则）。
- 无上榜 = 无交叉（席位方向缺失时 `seat_vs_main=None`）。

### D25. 产业资本“回购”数据源接入（2026-09-29）
- 背景：原 `_industrial` 只有股东增减持（E2 `increase/reduce`），无独立“回购”。
- 实测：**Tushare `repurchase`（股票回购）接口当前 token 可用**（返回 公告日/进度/数量/金额/价格上下限）；AKShare 亦有 `stock_repurchase_em` 可备选。
- **决策：接入 Tushare `repurchase`** → events E2 新增 `event_type="buyback"`（`_fetch_repurchase`，按代码，随 `download_all_corp_events`/`update_events` 更新）；`capital_profiler._industrial` 计入回购金额（阈值沿用 1 亿）。
- 产出：产业资本方向 = 回购/增持金额（≥1亿）为买入；有减持/质押为卖出。
